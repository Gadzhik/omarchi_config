# Горячие клавиши в русской раскладке

**Настроено 2026-07-29.** Раскладки `us,ru`, переключение Alt+Shift.

Проблема одна и та же на трёх уровнях, но решается по-разному: оконный менеджер,
терминал и синтез клавиш сопоставляют сочетания с клавишами независимо друг от друга.

---

## Уровень 1 — Hyprland (`home/.config/hypr/input.lua`)

```ini
resolve_binds_by_sym = false
```

`false` = резолвить по **позиции клавиши** первой раскладки (`us`),
`true` = по напечатанному символу.

Поэтому в `kb_layout` латинская раскладка обязана стоять **первой**: `us,ru`.
Если поставить `ru,us`, все `SUPER+<буква>` начнут резолвиться против кириллицы.

Этого достаточно для всех биндингов Hyprland, но **внутрь терминала не достаёт** —
там своя логика обработки клавиш.

---

## Уровень 2 — Alacritty (`home/.config/alacritty/alacritty.toml`)

### Почему ломалось

Alacritty сопоставляет биндинги с **символом**, который выдаёт активная раскладка.
В русской `Ctrl+A` приходит как `Ctrl+ф`. Символ `ф` не входит в ASCII, управляющий
код `^A` из него не выводится — и в шелл не уходит **вообще ничего**. Не «работает
неправильно», а молча проглатывается.

Ломались все `Ctrl+<буква>` (прерывание, поиск по истории, перемещение по строке) и
все `Alt+<буква>` (readline-перемещение по словам).

### Решение

62 явных биндинга для кириллицы, сопоставленных **по позиции клавиш ЙЦУКЕН**:

| группа | что покрывает |
|---|---|
| `Ctrl` + 26 букв | управляющие коды `^A`..`^Z` |
| `Ctrl+х`, `Ctrl+ъ` | `Escape` (``) и `^]` — важно для vim |
| `Alt` + 26 букв | `ESC` + латинская буква (readline) |
| `Ctrl+Shift+с/м/а/и` | Copy / Paste / SearchForward / SearchBackward самого Alacritty |

Man-страница разрешает это прямо: *«The regular keys like "A", "0", and **"Я"** can be
mapped directly»*.

### Почему не scancode

Alacritty умеет и scancode (`key = 30`), и это было бы раскладко-независимо одной
записью на клавишу. Но нумерация не документирована однозначно (evdev или X11-keycode,
то есть со сдвигом на 8), а ошибка привязала бы биндинги к не тем клавишам молча.
Кириллические символы проверяемы глазами и не зависят от догадок.

### ⚠️ Привязка к ЙЦУКЕН

Соответствия жёстко завязаны на стандартную русскую раскладку. Смена `kb_variant`
(например на `ru,phonetic`) их сломает.

Генератор блока — `scripts/gen-cyrillic-bindings.py`. Таблица соответствий там в
одном месте (`M`), переписать под другую раскладку — минутное дело:

```bash
python3 scripts/gen-cyrillic-bindings.py    # печатает блок в stdout
```

### Проверка

Переключиться на русский и попробовать: `Ctrl+С` (прервать), `Ctrl+К` (поиск по
истории), `Ctrl+Ф` / `Ctrl+У` (начало и конец строки), `Ctrl+Г` (убить строку).

Валидность TOML после правки:

```bash
python3 -c "import tomllib; d=tomllib.load(open('$HOME/.config/alacritty/alacritty.toml','rb')); print(len(d['keyboard']['bindings']),'биндингов')"
```

Применяется живой перезагрузкой (`live_config_reload` включён по умолчанию):
`omarchy restart terminal` — просто трогает файл, сессии не убивает.

## Уровень 3 — синтез клавиш (`home/.config/hypr/bindings.lua`)

**Найдено 2026-09-09 на Omarchy 4.0.3.**

Уровни 1 и 2 — про то, как сочетание **распознаётся**. Этот — про то, как клавиша
**отправляется**, и `resolve_binds_by_sym` здесь не помогает вообще.

### Почему ломалось

Omarchy 4 добавил «универсальный» буфер обмена: `SUPER+C` / `SUPER+V` / `SUPER+X`
шлют в сфокусированное окно `Ctrl+C` / `Ctrl+V` / `Ctrl+X`, а в терминале —
`Ctrl+Insert` / `Shift+Insert`. Клавиша передаётся **по имени**:

```lua
-- /usr/share/omarchy/default/hypr/bindings/clipboard.lua
hl.dispatch(hl.dsp.send_key_state({ mods = "CTRL", key = "C", state = "down" }))
```

Hyprland ищет это имя в **активной** группе раскладки. В русской латинской `C` нет:

```
key <AB03> {  symbols[1] = [ c, C ]   symbols[2] = [ Cyrillic_es, Cyrillic_ES ]  };
key <AB04> {  symbols[1] = [ v, V ]   symbols[2] = [ Cyrillic_em, Cyrillic_EM ]  };
```

Итог — не «другое действие», а падение с оверлеем Hyprland в правом верхнем углу:

```
Runtime error in lua:
=[C]:-1: send_key_state: key not found
```

Сам бинд при этом распознаётся правильно — ломается только то, что он делает внутри.

### Решение

Те же три бинда переопределены в `bindings.lua` (с `hl.unbind` перед каждым), но
клавиша передаётся **кодом**, а он у физической клавиши один во всех раскладках:

| клавиша | X11-код | xkb-алиас |
|---|---|---|
| `x` | 53 | `<LatX>` |
| `c` | 54 | `<LatC>` |
| `v` | 55 | `<LatV>` |

```lua
o.bind("SUPER + C", "Universal copy", universal_clipboard_shortcut("CTRL", "code:54", "CTRL", "Insert"))
```

`Insert` оставлен именем — он есть в обеих группах, ломать нечего.

Проверено под `ru` и `us`. Здесь `code:` сработал, в отличие от Alacritty (уровень 2),
где от scancode отказались из-за неоднозначной нумерации: у Hyprland она документирована
как X11-код, и его видно прямо в `xkbcli compile-keymap`.

### Как воспроизвести диагноз

```bash
xkbcli compile-keymap --layout "us,ru" --options "grp:alt_shift_toggle" | grep -A3 "key <AB03>"
```

Ошибка нигде не логируется — ни в `hyprland.log`, ни в `journalctl`, ни в
`hyprctl rollinglog`. Живёт только в оверлее на экране.

## Другие терминалы

В `~/.config/` лежат конфиги foot, kitty и ghostty, но установлен только Alacritty,
поэтому правился он один.

Если переходить на **ghostty** — там это решается изящнее, у него есть префикс
`physical:` для привязки к позиции клавиши независимо от раскладки:

```
keybind = physical:ctrl+c=text:\x03
```
