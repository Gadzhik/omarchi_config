# LM Studio на Omarchy — настройка производительности

Подготовлено под эту машину: Intel Core Ultra 5 125H (14 ядер / 18 потоков),
встроенная **Intel Arc Graphics (Meteor Lake)**, 30 ГБ ОЗУ, без дискретной
видеокарты. LM Studio `0.4.20` из AUR (`lmstudio-bin`).

---

## 1. Что уже настроено правильно

| Параметр | Значение | Комментарий |
|---|---|---|
| Движок | `llama.cpp-linux-x86_64-vulkan-avx2 @ 2.27.1` | выбран автоматически, менять не нужно |
| Ускоритель | Intel Arc (MTL), Vulkan, 23.1 ГиБ | видеопамять выделяется из общих 30 ГБ |
| Драйвер | `vulkan-intel` + `mesa` | стоят в системе, доустанавливать нечего |

Проверить в любой момент:

```bash
export PATH="$HOME/.lmstudio/bin:$PATH"
lms runtime ls        # звёздочка у выбранного движка
lms runtime survey    # какое железо движок реально видит
```

Если в `survey` не окажется строки с Arc — значит выбран CPU-движок,
переключиться на Vulkan через `lms runtime select`.

## 2. Замеры на этой машине

Модель Qwen3.5-9B Q4_K_M, одинаковый запрос, 200 токенов на выходе:

| Режим | Скорость | Отличие |
|---|---|---|
| GPU (Vulkan) + `parallel 1` | **5.4 ток/с** | эталон |
| GPU (Vulkan) + `parallel 4` | 5.0 ток/с | −8 % |
| CPU (выгрузка выключена) | ~0.4 ток/с | в 13 раз медленнее |

Цифру для CPU считать оценкой снизу: замер сделан на Vulkan-движке с
отключённой выгрузкой, а не на отдельной CPU-сборке. Для практического вывода
это неважно — выгрузка на GPU выигрывает с большим запасом.

## 3. Настройки уровня модели

Правятся в панели загрузки модели — шестерёнка рядом с её названием.
**Через CLI они не сохраняются между запусками**, поэтому задавать нужно именно
в интерфейсе, тогда конфиг привяжется к модели.

### 3.1 GPU offload — на максимум

Ползунок числа слоёв вправо до упора. Все твои модели (6–12 ГБ) помещаются в
23 ГиБ целиком, дробить нет смысла.

Это самая важная настройка: разница между полной выгрузкой и её отсутствием —
больше десятикратной. Если модель не влезает целиком, выгружай сколько
поместится: частичная выгрузка всё равно быстрее чистого CPU.

### 3.2 Parallel → 1

По умолчанию стоит **4**. Это число одновременных запросов, и контекст делится
между ними на независимые слоты — при одиночной работе три четверти KV-кеша
простаивают, а сам ответ считается медленнее.

Ставить больше 1 стоит только если LM Studio раздаёт API нескольким клиентам
одновременно. В замере переход с 4 на 1 дал +8 %.

### 3.3 Flash Attention — включить

Сокращает расход памяти под механизм внимания, особенно заметно на длинном
контексте. На Vulkan работает.

### 3.4 Context length — не раздувать

Сейчас 8192, и это разумно. Контекст занимает память **всегда**, а не только
когда заполнен, и удлиняет обработку запроса. Поднимать до 32k имеет смысл под
конкретную задачу (разбор большого документа), а не «на всякий случай».

Ориентир: удвоение контекста примерно удваивает память под KV-кеш. При включённой
квантизации KV-кеша (если появится в настройках) расход падает вдвое ценой
небольшой потери качества.

## 4. Управление движками

Установленные сборки занимают заметное место. Посмотреть и почистить:

```bash
lms runtime ls
lms runtime remove <имя@версия>
```

Смысла держать не имеет:

- **CUDA-сборки** (`llama.cpp-linux-x86_64-nvidia-cuda-avx2`) — 1.1 ГБ,
  NVIDIA в этом ноутбуке нет, работать они не будут.
- **Старые версии** тех же движков — активна только одна, остальные лежат мёртвым грузом.

## 4a. ⚠️ gpt-oss-20b роняет GPU

При полной выгрузке на Arc модель **вешает видеодрайвер**:

```
Engine error: vk::Device::waitForFences: ErrorDeviceLost
kernel: i915 0000:00:02.0: [drm] llama-server[...] context reset due to GPU hang
```

Ядро сбрасывает контекст i915, запрос падает. Система переживает это без
последствий, но ответа не будет.

Это не вопрос скорости — модель на 12 ГБ просто не выдерживается этой связкой
драйвера и Vulkan-движка. Варианты:

- частичная выгрузка (сдвинуть ползунок слоёв примерно наполовину) — часть
  вычислений уйдёт на CPU, но GPU перестанет падать;
- полностью на CPU — медленно, но стабильно;
- не пользоваться ей на этой машине, взяв модель поменьше.

Стоит перепроверять после обновлений `mesa` / `vulkan-intel` и движка
llama.cpp — проблема на стороне драйвера и может уйти сама.

## 4b. Какие модели добавить

Твоя связка любит **маленькие плотные модели**. Ориентир: 9B Q4 = 5 ток/с,
значит 3–4B Q4 дадут примерно 12–15 ток/с — это уже комфортное чтение на лету.

| Задача | Что брать | Почему |
|---|---|---|
| Повседневные вопросы, быстрые ответы | модель **3–4B** в Q4 из семейства, которое уже проверено (Qwen3.5, Gemma 4) | втрое быстрее девятки, качества хватает для большинства запросов |
| Код | специализированная **coder**-модель на 7B в Q4 | обученные на коде модели на своём размере обходят универсальные |
| Длинные документы, рассуждения | текущая **Qwen3.5-9B** | лучший баланс качества и скорости из установленного |
| Embeddings для поиска по своим файлам | **nomic-embed-text** (уже стоит) | 84 МБ, работает на CPU, GPU не занимает |

Точные названия и версии смотри в поиске моделей внутри LM Studio — каталог
обновляется чаще, чем этот файл. Правила выбора:

- квантизация **Q4_K_M** — оптимум по соотношению качество/размер;
- размер файла должен быть заметно меньше 23 ГиБ, иначе выгрузка будет неполной;
- **MoE-модели** теоретически выгодны (активна лишь часть весов), но на этом
  железе есть риск того же сбоя, что с gpt-oss-20b — проверяй осторожно;
- **не держи всё сразу**: каждая модель это гигабайты на диске, а загружать в
  память всё равно можно только одну.

Установка из командной строки:

```bash
lms get <название-модели>
```

## 5. Чего ждать от этого железа

5 ток/с на модели 9B — честный потолок встроенной графики Meteor Lake. Упор идёт
в **пропускную способность памяти**, а не в настройки: у iGPU нет собственной
быстрой видеопамяти, она работает с теми же модулями, что и процессор. Никакой
конфигурацией это не обойти.

Что действительно меняет скорость:

- **Размер модели.** 3–4B в Q4 быстрее 9B примерно втрое.
- **Тип архитектуры.** MoE-модели (Mixture of Experts) активируют лишь часть
  весов на токен, поэтому идут заметно быстрее плотных моделей того же размера.
  Для слабого GPU это лучший выбор.
- **Квантизация.** Q4_K_M — разумный баланс. Q8 вдвое тяжелее при небольшом
  приросте качества, Q3 и ниже уже заметно глупее.
- **Питание.** На батарее скрипт `refresh-rate-by-power` переключает систему в
  `power-saver`, и скорость падает. Для серьёзной работы — от сети.

## 6. Соседи по ресурсам

Эти службы едят память и процессор в фоне, даже когда не используются:

```bash
sudo systemctl stop ollama     # свой сервер моделей, дублирует LM Studio
minikube stop                  # кластер Kubernetes, ~1.5 ГБ + постоянный CPU
```

Вернуть: `sudo systemctl start ollama`, `minikube start`.

## 7. Полезные команды

```bash
export PATH="$HOME/.lmstudio/bin:$PATH"

lms ls                    # модели на диске
lms ps                    # что загружено в память
lms load <модель> --gpu max --parallel 1
lms unload --all          # освободить память
lms server start          # OpenAI-совместимый API на localhost:1234
lms server status
```

Проверка API:

```bash
curl -s http://127.0.0.1:1234/v1/models | jq -r '.data[].id'
```

Через этот endpoint к локальным моделям подключаются сторонние клиенты —
редакторы, агентские надстройки, скрипты.
