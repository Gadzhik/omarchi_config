# Куда добавлять образы в GNS3

Пути на этой машине взяты из `~/.config/GNS3/2.2/gns3_server.conf`.
Версия GNS3 — 2.2.60.

---

## 1. Структура каталогов

```
~/GNS3/
├── images/          ← сюда кладутся образы
│   ├── QEMU/        ← qcow2, img, iso, vmdk — виртуалки
│   ├── IOS/         ← .image/.bin для Dynamips (классические роутеры Cisco)
│   └── IOU/         ← бинарники IOL/IOU
├── projects/        ← топологии и их временные диски
├── configs/         ← стартовые конфиги устройств
├── symbols/         ← иконки
└── appliances/      ← .gns3a, положенные вручную
```

Подкаталоги `QEMU`, `IOS`, `IOU` GNS3 создаёт сам при первом импорте. Если
нужного нет — создай, имя чувствительно к регистру.

Пути настраиваются в `gns3_server.conf`:

```ini
images_path = /home/igadzhi/GNS3/images
projects_path = /home/igadzhi/GNS3/projects
additional_images_paths =
```

`additional_images_paths` принимает дополнительные каталоги через `:` — удобно,
если образы лежат на другом диске и копировать их не хочется.

---

## 2. Три способа добавить образ

### Способ 1 — мастер импорта (рекомендуется)

`File → Import appliance`, указать `.gns3a`.

Мастер сам спросит версию, попросит файл образа, **скопирует его в
`~/GNS3/images/QEMU/`**, сверит MD5 и создаст шаблон со всеми параметрами из
рецепта. Файл можно указывать прямо из `~/Downloads` — переносить заранее не
нужно.

Это надёжнее ручного пути, потому что `.gns3a` содержит десяток настроек
(интерфейс диска, тип адаптеров, объём памяти, порядок загрузки), и пропуск
любой из них ломает запуск. Подробности — в разделе 5.

### Способ 2 — вручную

1. Скопировать образ в `~/GNS3/images/QEMU/`.
2. `Edit → Preferences → QEMU VMs → New`, указать образ и параметры.

Если файл уже лежит в этом каталоге, мастер импорта увидит его сам и покажет
версию как готовую к установке — скачивать повторно не придётся.

### Способ 3 — через API

Сервер слушает `localhost:3080` и **требует HTTP-аутентификацию**: пользователь
и пароль лежат в `gns3_server.conf`. Без них ответ — 401.

```bash
U=admin; P=$(grep -oP '^password\s*=\s*\K.*' ~/.config/GNS3/2.2/gns3_server.conf)
curl -s -u "$U:$P" http://127.0.0.1:3080/v2/templates | jq -r '.[].name'
```

Создание шаблона — `POST /v2/templates`. Способ хорош для скриптов, но требует
задать все параметры руками (см. раздел 5).

---

## 3. Docker-приложения — файл не нужен

Если в `.gns3a` есть секция `docker` вместо `qemu`, образ тянется из реестра
автоматически при создании первого узла. Ничего скачивать и никуда класть не
надо.

Проверить, что скачалось: `docker images`.

---

## 4. Проверка подлинности

Для каждой версии в `.gns3a` записаны точный размер и контрольная сумма:

```
файл:   chr-7.22.1.img
размер: 134217728
md5:    a67290634f489071eae2fd99dcadba86
```

Мастер сверяет их автоматически. Вручную:

```bash
md5sum ~/GNS3/images/QEMU/chr-7.22.1.img
jq -r '.images[] | select(.filename=="chr-7.22.1.img") | .md5sum' mikrotik-chr.gns3a
```

Совпадение означает, что файл — оригинал вендора, а не чья-то пересборка.

## 5. Обязательные параметры QEMU-шаблона

При ручном создании шаблона легко пропустить поле и получить неработающий узел.
Все значения берутся из секции `qemu` файла `.gns3a`:

| Поле | Что будет, если пропустить |
|---|---|
| `hda_disk_interface` | **узел не загрузится** — см. ниже |
| `adapter_type` | интерфейсы могут не определиться гостевой ОС |
| `adapters` | не хватит портов для линков |
| `ram` | падение или отказ загружаться |
| `boot_priority` | загрузка не с того носителя |
| `options` | пропадут вендорские флаги вроде `-nographic` |

### Симптом пропущенного `hda_disk_interface`

GNS3 подставляет `none`, и QEMU получает диск как `if=none` без устройства —
объявленный, но ни к чему не подключённый. Виртуалка не находит носитель и
уходит в сетевую загрузку. На VGA-консоли видно:

```
iPXE 1.20.1+ -- Open Source Network Boot Firmware
No bootable device.
```

Лечится указанием интерфейса (`virtio`, `ide`, `sata` — смотри `.gns3a`) в
свойствах шаблона и узла, после чего узел перезапускается.

## 6. Диски внутри проекта

Файл в `~/GNS3/images/` — **эталон, он не изменяется**. При добавлении узла
GNS3 создаёт в каталоге проекта qcow2-overlay поверх него:

```
~/GNS3/projects/<id>/project-files/qemu/<node-id>/hda_disk.qcow2
```

Отсюда два следствия: один образ обслуживает сколько угодно узлов, а сброс
устройства к заводскому состоянию — это просто удаление узла. Свежий overlay
весит около 200 КБ, растёт по мере записи.

Удалять образ из `images/`, пока на него ссылаются проекты, нельзя — overlay
без backing-файла станет нерабочим.

---

## 7. Если консоль молчит

Некоторые образы (в частности MikroTik CHR) выводят всё на **VGA**, а не в
serial-порт, хотя в шаблоне указан `console_type: telnet` и флаг `-nographic`.
В графическом интерфейсе GNS3 консоль открывается нормально, а вот подключиться
к порту telnet скриптом не выйдет — там будет тишина.

Посмотреть, что реально на экране, можно снимком через монитор QEMU:

```bash
MON=$(pgrep -af qemu-system-x86_64 | grep -oE 'monitor tcp:127.0.0.1:[0-9]+' | grep -oE '[0-9]+$')
printf 'screendump /tmp/vm.ppm\n' | timeout 5 nc 127.0.0.1 $MON >/dev/null
magick /tmp/vm.ppm /tmp/vm.png
```

Приём выручает, когда узел вроде бы запущен, но признаков жизни не подаёт.

## 8. Порядок действий для нового образа

1. Скачать образ у вендора (ссылка есть в самом `.gns3a`, поле
   `direct_download_url`).
2. Распаковать, если он в архиве.
3. `File → Import appliance` → выбрать `.gns3a` → версию → файл образа.
4. Дождаться проверки MD5.
5. Перетащить узел в топологию, запустить, открыть консоль.
6. Если не стартует — сверить `hda_disk_interface` и `boot_priority` с `.gns3a`.
